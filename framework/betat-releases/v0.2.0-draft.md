## Betat Community Framework v0.2.0

*The human record, for the other person.*

---

### What's new in v0.2

v0.2 addresses the ocean of existing human-originated content
created before communities began recording provenance at creation
time, makes Betat a connected network of communities rather than
a collection of independent instances, and introduces a richer
optional UI layer for communities that want it.

The bundled Django UI that ships with v0.1 remains the default —
`pip install betat-community` gives you a working community
interface immediately, no additional setup. v0.2 adds a Next.js
interface as an opt-in for communities that want a richer,
more polished experience. The choice is the operator's; both
paths talk to the same federation API.

---

### Next.js community interface (opt-in)

The bundled Django UI is the zero-configuration default.
The Next.js interface is Layer 3 — an optional richer frontend
that communities can deploy alongside or instead of the bundled UI.

**Why Next.js over plain React:**
Server-side rendering means every page is publicly indexable —
search engines can crawl timeline nodes, community records, and
Provenancier profiles. First-load performance is fast on mobile
because pages are pre-rendered, not assembled in the browser.
Routing, data fetching, and static generation are built in —
operators don't configure these separately. Plain React requires
managing all of this by hand, which adds complexity that compounds
across a project's lifetime.

**What the Next.js interface adds over the bundled UI:**
- Richer timeline tree visualization — interactive, animated,
  decade-indexed with smooth lazy loading
- Mobile-first design with proper touch interactions
- Search engine indexable timeline nodes and record pages
- Community branding customization without editing Django templates
- Faster page transitions and optimistic UI updates
- A foundation for multilingual support (Phase 3)

**How the opt-in works:**
During `betat init` or the browser setup wizard, the operator
is offered a choice:

```
Community interface:
  [1] Bundled UI (default) — included with the framework,
      ready immediately, no additional setup required.

  [2] Next.js UI (richer) — install separately after setup.
      Requires Node.js 18+. Recommended for communities that
      want a more polished public-facing interface.
```

Choosing option 2 sets a flag in `CommunityConfig`. After setup:

```bash
# Install the Next.js interface (separate package):
npx create-betat-ui@latest

# Configure it to point at your community's API:
# Edit .env.local:
BETAT_API_URL=https://your-community-domain.org/betat/

# Run:
npm run dev      # development
npm run build    # production
npm start        # serve
```

The Next.js interface lives at a separate domain or subdomain
(e.g. `ui.your-community.org`) and reads exclusively from the
federation API — no direct database access, no Django dependency
at runtime.

**The bundled UI is never deprecated.** Communities that choose
the bundled UI are fully supported indefinitely. The Next.js
interface is an addition, not a replacement.

**The Next.js interface ships as a separate repository:**
`github.com/Sylva-AF/betat-ui`

This keeps the Python framework and the JavaScript frontend
on separate release cycles. A UI improvement doesn't require
a framework release; a framework change doesn't require a UI
rebuild. Contributors who work in JavaScript work in `betat-ui`;
contributors who work in Python work in `betat-repo`.

### Timeline tree and backfill mechanism

The timeline is a public-facing visualization of human-originated
content discovered across the internet, indexed by year of creation.
Visible to everyone. Enrolled Provenanciers assert or flag content.
Confirmed content enters the community's verification queue and
becomes a permanent Betat record.

**Why it exists:** content created before Betat adoption has no
provenance record. The backfill mechanism addresses this retroactively,
with a natural lifecycle — it runs intensively at launch, narrows as
adoption grows, and eventually becomes a background process. When the
gap closes, the backfill mechanism is deprecated. That is the correct
outcome.

**For the public:**
- Browse at `/community/timeline/`
- Year-indexed, loads by decade — designed for mobile users on
  constrained connections first
- Under 10KB on first load — the full article is never fetched
  unless you click through to the source
- Every timeline node is search-engine indexable (Next.js UI)
  or server-rendered (bundled UI)

**For enrolled Provenanciers:**
- Assert human origin on any discovered node
- Flag content as AI-generated, fake, or impersonation
- Personal knowledge is what makes assertions valuable — a local
  expert asserting on content they know firsthand is more
  meaningful than an algorithmic guess
- The enrollment trigger: anonymous visitors who find content
  they have personal knowledge about are prompted to enroll
  when they try to assert. The timeline is the discovery surface
  that converts public interest into community membership.

**For community operators:**
- `betat backfill start` launches the discovery agent
- `betat backfill stop` releases claims gracefully
- The agent discovers metadata only — never full articles
- Metadata cached as static JSON, served via GitHub Pages
  at zero infrastructure cost
- Agent paces itself to the community's verification capacity

**Agent conflict resolution — the coverage map:**
Multiple communities share a coverage map at betat.org. Before
claiming content, an agent checks whether another community has
already covered it. Covered content is skipped. Claims expire
after 72 hours — abandoned work is automatically released.

### Cross-community network features

**Cross-community enrollment (recognition requests):**
A Provenancier enrolled in Community A who wants to join Community B
submits a recognition request carrying proof of their existing
verification. Community B's admin reviews and decides independently.
On approval, Community B issues its own token. Credentials do not
transfer automatically — trust between communities is earned, not
assumed.

**Provenancier-to-operator growth path:**
Any enrolled Provenancier can independently start a new community
via `betat init` on a domain they control. No permission required
from their source community. The new community is fully sovereign.

**Community trust declarations:**
Communities can declare trust relationships with other communities
in the registry — signaling that recognition requests from those
communities' members will be viewed favorably. Never automatic
access; always an admin decision.

**Registry network graph:**
The registry shows which communities spawn new communities, which
Provenanciers become operators, how knowledge domains expand.
Organic growth made visible, not engineered.
